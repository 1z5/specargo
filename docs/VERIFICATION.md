# 校验机制：句子级漏读三态判定

本文解释校验端的工作原理、指标定义与防漏读的工程建议。
**只讲方法与阈值标定过程，不含任何真实业务数据。**

## 1. 为什么需要校验

TTS 模型对长文本（数百词/章）存在**静默截断**现象：API 正常返回、无报错，
但音频只覆盖原文的一部分。由于生成时无任何告警，漏读是"静默故障"，
必须用 ASR 转录 + 原文对比来检测。

这类故障的危险在于：**所有上游信号都是绿的**。日志成功、退出码 0、文件生成了，
但内容不对。所以校验必须是**独立于生产链路**的第二双眼睛。

## 2. 检测原理：句子级漏读判定

**核心思想：直接回答"哪句没读到"，容忍转录端的零星听错。**

词级严格对比有个致命问题：ASR 听错个别词（人名、术语）也会被算作"缺失"，
覆盖率永远 <100%，无法区分"个别词听错"与"整句漏读"。

句子级检测的做法：

1. 原文按句切分（句号/问号/感叹号）
2. 每句归一化后在转录全文中模糊匹配（滑动窗口 + SequenceMatcher），取最佳相似度
3. **三态判定**（相似度 = sim）：

| sim 区间 | 句子状态 | 含义 |
|---|---|---|
| sim ≥ 0.7 | FOUND | 已读（听错 1~2 词仍 >75%） |
| 0.5 ≤ sim < 0.7 | **UNSURE** | 疑似：转录听错严重或措辞差异大，**无法确证**，需人工抽听 |
| sim < 0.5（且句长 > 2 词） | MISSING | 确证漏读，报告列出句子原文 |
| 句长 ≤ 2 词的短句 | UNSURE | 短句听错时相似度可能为 0，文本上无法区分，一律人工确认 |

4. 文件状态：有 MISSING → `FAIL_MISSING`；仅有 UNSURE → `WARN`；
   准确率不足 → `FAIL_ERRORS`；否则 `PASS`
5. 退出码：0 = 无确证漏读（WARN 不阻塞），1 = 存在 FAIL

## 3. 为什么需要三态（方法论，比结论重要）

二态（已读/漏读）会同时踩两个坑：

- **一刀切判漏读 → 误报**：ASR 的严重听错（同音词、连读、数字读法）相似度落在 0.5~0.67，
  它们其实**读到了**。全判 FAIL 会污染 FAIL 的可信度，人工核几遍就不再信报告。
- **提高宽容度 → 漏报**：真漏读的整句相似度可以低到 0。

**解法是把"无法确证"显式建模成第三态**：UNSURE 不影响 FAIL 的可信度，也不漏报，
交人工抽听。这是"用状态机分离确定性"的典型做法——和批处理里把
"环境失败（可重试）/ 数据失败（进隔离区）/ 系统失败（停下来告警）"分开是同一个思路。

## 4. 阈值怎么定：按实测分布，不拍脑袋

阈值不能凭感觉设，要看**两类样本的相似度分布是否分离**：

| 情况 | 相似度分布 | 判定 |
|---|---|---|
| 确证漏读（整句消失/截断） | 0 ~ 0.36 | MISSING |
| 严重听错但已读 | 0.50 ~ 0.67 | UNSURE |
| 已读（轻微听错） | 0.78 ~ 1.0 | FOUND |

三簇分离时，阈值落在簇间空隙里（0.5 / 0.7）。**判据是"分布是否分离"，
不是"阈值是多少"**——换语种、换 ASR 模型、换内容类型都必须重新标定，
这是已知未验证项，不是通用常数。

## 5. 归一化：先消除"写法 vs 读法"差异再比对

模糊匹配前先归一化，否则同样的音频覆盖率会差 10 个百分点以上：

- 大小写、标点剥离（`don't` → `dont`）
- 数字词 → 数字（`fourteen` → `14`，`twenty four` → `24`）
- **数字占位**：所有数字统一为 `#`（消除 `14` vs `fourteen` vs `0.6` 的读法差异）
- **连字符双形态**：`fight-or-flight` 可能读作 "fight or flight"（split 形态）
  或连读成 "fightorflight"（join 形态），两种形态都匹配取最高分

## 6. 已知盲区（诚实边界）

1. **ASR 与 TTS 存在共享失效模式**：两者都是模型，"校验通过"只等于
   "在 ASR 能力范围内没发现漏读"。缓解路径：异厂商 ASR 交叉验证、
   用 VAD/音频时长做独立信号源、UNSURE 一律人工抽听。
2. **阈值不跨语种/跨模型通用**：换场景必须重新标样本画分布。
3. **校验本身有成本**：转录耗时与音频时长同量级，大批量要并行 + 缓存。

## 7. 工程化建议

- **增量处理**：已有转录缓存则跳过（`--force` 强制重转）
- **原文快照**：生成时落盘 `.input.txt`，校验优先读它（比解析调用日志精确），
  同时作为输入指纹用于断点续跑
- **结构化报告**：`report.json`（机器可读，接 CI/修复流程）+ `report.md`（人工可读）
- **自动修复**：`--fix` 对 FAIL 文件按原文重新生成并复检，
  覆盖原文件前先备份，复检仍失败则回滚
- **存量自愈**：只有调用日志的旧音频，自动补写 `.input.txt` 便于后续精确对比
